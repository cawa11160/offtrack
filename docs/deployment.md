# Deployment

Offtrack production runs best as:

- Frontend: Vercel
- Backend API: Render web service
- Database: Render Postgres
- Media: Cloudflare R2 or S3-compatible storage
- Recommender artifacts: Postgres via `RECOMMENDER_ARTIFACT_STORE=database`

This keeps musician uploads and recommender learning independent from a single server disk.

## Vercel Frontend

Project root:

```text
frontend
```

Build settings:

```text
Install Command: npm ci
Build Command: npm run build
Output Directory: dist
```

Required env vars:

```text
VITE_API_BASE_URL=https://<render-backend-host>
VITE_MAPBOX_TOKEN=
VITE_TICKETMASTER_API_KEY=
VITE_DEFAULT_EVENT_CITY=New York
VITE_DEFAULT_EVENT_STATE_CODE=NY
VITE_DEFAULT_EVENT_COUNTRY_CODE=US
```

`frontend/vercel.json` only handles SPA routing. API traffic goes directly to the Render backend through `VITE_API_BASE_URL`.

## Render Backend

Use the committed `render.yaml` as the blueprint. Before the first deploy, fill every `sync: false` env var in Render.

Required backend env vars:

```text
FRONTEND_URL=https://<vercel-host>
ALLOW_ORIGINS=https://<vercel-host>
S3_BUCKET=<r2-or-s3-bucket>
S3_ENDPOINT_URL=https://<cloudflare-account-id>.r2.cloudflarestorage.com
S3_ACCESS_KEY_ID=<r2-access-key>
S3_SECRET_ACCESS_KEY=<r2-secret-key>
S3_PUBLIC_BASE_URL=https://<optional-cdn-host>
SPOTIFY_CLIENT_ID=
SPOTIFY_CLIENT_SECRET=
SPOTIFY_REDIRECT_URI=https://<render-backend-host>/api/spotify/callback
OPENAI_API_KEY=
```

Generated by Render:

```text
DATABASE_URL
JWT_SECRET
COOKIE_SECRET
ADMIN_API_KEY
```

Production defaults in the blueprint:

```text
OFFTRACK_ENV=production
MEDIA_STORAGE_BACKEND=r2
RECOMMENDER_ARTIFACT_STORE=database
RECOMMENDER_PROMOTION_GUARDRAILS=true
COOKIE_SECURE=true
SPOTIFY_COOKIE_SECURE=true
TRUST_PROXY_HEADERS=true
```

The backend intentionally fails startup in production if:

- `FRONTEND_URL` is not HTTPS.
- `ALLOW_ORIGINS` is missing, wildcarded, or localhost.
- media storage is local without an explicit override.
- R2/S3 credentials are missing.
- JWT/cookie secrets are weak defaults.

## Recommender Operations

The Render cron service runs hourly:

```bash
python recommender_agent.py build
```

With `RECOMMENDER_ARTIFACT_STORE=database`, each promoted reward artifact is saved in Postgres and the active artifact is marked `current`. The admin recommender dashboard can build, evaluate, list, train, and roll back artifacts without relying on local files.

Manual checks:

```bash
curl https://<render-backend-host>/api/ping
curl https://<render-backend-host>/api/db_status
```

Run database migrations after every backend deploy that includes an Alembic revision:

```bash
alembic upgrade head
```

For the current production batch, confirm the latest revision is applied:

```bash
alembic current
```

The expected head includes `20260530_0007`, which adds real notifications and upload-level discovery controls.

Admin recommender checks:

```bash
curl -H "X-Admin-Api-Key: $ADMIN_API_KEY" \
  https://<render-backend-host>/api/admin/recommender/metrics

curl -H "X-Admin-Api-Key: $ADMIN_API_KEY" \
  https://<render-backend-host>/api/admin/recommender/artifacts
```

## Release Smoke Test

After every production deploy:

1. Visit the Vercel app and sign up/login.
2. Search for a song and request recommendations.
3. Pick a recommendation and confirm the picker closes.
4. Upload a test artist track and confirm playback works.
5. Pause discovery for that upload, request recommendations, then resume discovery and confirm the track can re-enter discovery.
6. Trigger a listener action on the upload and confirm the artist notification drawer shows the event.
7. Open the musician dashboard and confirm conversion paths, paused discovery count, and track-level discovery scores render without overlap.
8. Open the profile page and confirm listening graphs do not overlap.
9. Open `/admin/recommender`, refresh metrics, build an artifact, and verify it appears in the artifact list.
10. Check Render logs for startup guardrail failures and request errors.

## Beyond Launch

Next production upgrades:

- Move rate limiting to Render Key Value or Upstash Redis and set `RATE_LIMIT_BACKEND=redis`.
- Add PostHog dashboards for recommendation impressions, saves, skips, artist clicks, upload exposure, and conversion paths.
- Add a canary recommender flow before auto-promoting new ranker artifacts.
- Add email delivery for verification and artist notifications.
- Add R2 lifecycle policies and backups for uploaded audio.
- Add a notification email worker so high-value listener signals reach artists even when they are not in the app.
- Add a recommender promotion gate that compares artist discovery lift, listener retention, and skip rate before promoting new artifacts.
